# TRACE 조사 가이드 (팀 작성 내부 기준, 공정 전문가 검증 전)

## 비교 기준 run 선택
같은 장비, 같은 recipe의 대상 이전 run을 참조로 쓴다. 고장 기록 직전 24시간 안에 끝난 run은 이미 이상이 진행 중이었을 수 있으므로 정상 기준에서 제외한다. 참조가 3건 미만이면 비교하지 말고 사용자에게 범위 확대(다른 recipe 또는 다른 장비)를 물어본다.

## z-score 해석
z는 대상 run의 step별 센서 평균이 참조 run 평균들의 분포에서 얼마나 떨어졌는지를 나타낸다. |z| 3 이상은 '확인 필요 편차'로 보고, 2~3은 '경미한 편차'로 표현한다. 참조 표준편차가 0에 가까우면 아주 작은 차이도 큰 z가 되므로 실제 평균 차이(target_mean - ref_mean)를 함께 적는다. 센서값은 표준화된 값이라 물리 단위로 말하지 않는다.

## FlowCool 관련 확인 순서
FlowCool 계열 고장 이력이 있으면 FLOWCOOLPRESSURE, FLOWCOOLFLOWRATE의 편차를 먼저 본다. 유량은 정상인데 압력만 벗어나면 회로 상태 확인 후보로, 챔버 압력(IONGAUGEPRESSURE)이 함께 움직이면 웨이퍼·O-ring 경계 누설을 추가 확인 후보로 기록한다. 이는 조사 가설이며 원인 확정이 아니다.

## 보고서 작성 원칙
보고서는 FACTS(비교 조건과 계산 결과), EVIDENCE(데이터 run_id와 문서 출처), NEXT ACTION(추가 확인 항목과 사람이 판단할 지점), UNKNOWN(확인하지 못한 것)으로 나눈다. 원인을 단정하지 않고, 도구 결과에 없는 숫자를 쓰지 않는다. 근거 문서를 찾지 못했으면 찾지 못했다고 쓴다.

## 승인과 저장
조사 기록은 공정 엔지니어가 승인한 뒤에만 저장한다. 수정 요청이 오면 지적 사항을 반영해 보고서를 다시 작성하고 다시 승인을 받는다.
