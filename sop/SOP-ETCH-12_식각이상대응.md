# SOP-ETCH-12 식각 장비 이상 대응

| 항목 | 내용 |
|---|---|
| 문서 ID | SOP-ETCH-12 |
| 개정 | Rev 0.1 (예시, 2026-10-20) |
| 적용 장비 | 플라즈마 식각 장비 전 챔버 (예: ETCH-07, ETCH-09) |
| 문서 소유 | 식각 공정 engineer |
| 관련 문서 | SOP-SAFE-01, WI-PM-07, SPEC-RF-03, WI-MFC-02, SPEC-EPD-01, SOP-FC-01 |

> 수치 기준 중 `[예시]` 표시는 시연용 값이다. 장비 매뉴얼과 공정 스펙으로 확정하기 전에는 판정에 쓰지 않는다.

## 1. 목적

식각 장비에서 이상이 감지된 순간부터 생산 복귀까지 누가 무엇을 어떤 순서로 하는지 정한다. 원인을 추측으로 단정하지 않고, run 비교와 문서 조항에 근거해 조치를 결정하게 한다.

## 2. 적용 범위

- 생산(Productive)·엔지니어링(Engineering) run 중 발생한 모든 장비 알람, SPC 관리 이탈(OOC), 후속 계측에서 보고된 식각 결과 이상
- 이온 밀(IBE) 장비의 FlowCool 이상은 SOP-FC-01을 함께 따른다.

## 3. 역할과 권한

| 역할 | 할 일 | 하지 않는 일 |
|---|---|---|
| worker (설비 오퍼레이터) | 알람 인지, 장비 hold, 장비 상태 전환, 최초 접수(TRACE 질문 등록), 재질문 응답 | 원인 판정, 조치 승인 |
| engineer (공정·설비 엔지니어) | 조사, 원인 가설 판단, 조치 결정, 보고서 승인·수정 요청, 생산 복귀 승인 | — |
| admin | 전체 조회, 문서·기준 관리 | 보고서 검토·승인 |

## 4. 절차

### 4.1 감지와 즉시 조치

1. 아래 중 하나가 발생하면 이 SOP를 시작한다.
   - 장비 인터락 알람 (RF, 압력, 가스, 냉각, 진공)
   - SPC 관리 한계 이탈: etch rate, endpoint 시간, RF reflected power, 챔버 압력
   - 후속 계측(CD, 잔막, 파티클)에서 해당 챔버가 원인으로 지목됨
2. worker는 진행 중 웨이퍼를 아래처럼 처리한다.
   - 인터락 알람: 장비가 자동 abort한 상태를 유지하고 재시작하지 않는다.
   - SPC 이탈: 현재 웨이퍼 처리를 끝낸 뒤 해당 챔버에 다음 lot을 넣지 않는다(hold).
3. worker는 장비 상태를 **Unscheduled downtime**으로 바꾼다 (SOP-SAFE-01 §2).
4. worker는 TRACE에 다음을 포함해 접수한다: 장비·챔버, recipe, 마지막 정상 run 이후 처리한 run, 알람 코드와 발생 시각, 영향받은 웨이퍼·lot ID.

### 4.2 Endpoint 지연 시 동시 비교

Endpoint가 기준 대비 10% 이상 지연되면 RF, 압력, 가스 유량 이력을 함께 비교한다.

- 기준은 §4.3에서 고른 정상 run들의 endpoint 시간 중앙값이다.
- 5% 이상 10% 미만 지연은 `[예시]` **주의**로 기록하고, 같은 챔버에서 연속 3 run `[예시]` 반복되면 10% 지연과 같은 절차를 따른다.
- endpoint 지연 하나만 보고 window 오염(SPEC-EPD-01)으로 단정하지 않는다. RF·압력·가스 중 함께 움직인 계통이 있으면 그 계통 문서를 먼저 연다.

### 4.3 비교 기준 run 선택

1. 같은 장비·같은 챔버·같은 recipe의 대상 이전 run을 기준으로 쓴다.
2. 이상 기록 직전 24시간 `[예시]` 안에 끝난 run은 이미 이상이 진행 중이었을 수 있으므로 기준에서 뺀다.
3. 마지막 PM 이전 run과 이후 run을 섞지 않는다. PM 직후 seasoning run은 기준에서 뺀다 (WI-PM-07 §3.6).
4. 기준 run이 3건 미만이면 비교하지 않고, engineer에게 범위 확대(다른 챔버 또는 다른 recipe)를 물어본다.

### 4.4 계통별 1차 점검 분기

| 함께 관찰된 신호 | 먼저 볼 문서 | 1차 점검 |
|---|---|---|
| RF reflected power 상승 | SPEC-RF-03 §2.4 | match network 접점, calibration |
| 챔버 압력 불안정 + etch rate 저하 | WI-MFC-02 §5.3 | MFC zero, leak rate |
| endpoint 지연만 단독 | SPEC-EPD-01 §6.2 | window 오염 → gain → 광원 |
| etch rate·endpoint가 PM 이후 서서히 drift | WI-PM-07 §3.1 | 폴리머 누적, 마지막 wet clean 이후 RF 시간 |
| He 후면 냉각 압력·유량 이상 (IBE) | SOP-FC-01 §4 | FlowCool 회로, O-ring |

여러 계통이 동시에 움직이면 비용이 작고 장비를 열지 않아도 되는 점검(설정·이력·calibration 기록)부터 한다.

### 4.5 원인 가설과 조치 결정

1. 조사 보고서는 FACTS(비교 조건과 계산 결과), EVIDENCE(근거 run ID와 문서 조항 ID), NEXT ACTION(확인할 항목과 사람이 판단할 지점), UNKNOWN(확인하지 못한 것)으로 나눈다.
2. 원인은 **확인 가설**로만 쓴다. 각 가설에는 근거 조항 ID를 최소 1개 붙인다. 근거 조항이 없으면 "근거 문서 없음"이라고 쓴다.
3. engineer가 보고서를 승인해야 조치를 시작한다. 수정 요청이 오면 지적 사항을 반영한 뒤 다시 승인받는다.
4. 장비를 여는 조치는 SOP-SAFE-01의 LOTO를 먼저 한다.

### 4.6 재인증과 생산 복귀

1. 조치가 끝나면 monitor wafer `[예시]` 3매로 etch rate, 균일도, 파티클을 측정한다.
2. 측정값이 모두 §4.3 기준 run 분포 안 (`[예시]` 중앙값 ±3%)에 들면 engineer가 복귀를 승인하고, worker가 장비 상태를 **Productive**로 바꾼다.
3. 재인증에 2회 연속 실패하면 §4.7로 올린다.

### 4.7 에스컬레이션

| 조건 | 대상 |
|---|---|
| Unscheduled downtime이 `[예시]` 4시간 넘게 원인 가설을 못 좁힘 | 설비 파트장 |
| 재인증 2회 연속 실패 | 설비 파트장 + 장비 업체 |
| 같은 원인으로 30일 `[예시]` 안에 2회 재발 | 공정 기술 회의 안건 |
| 안전 관련 알람 (가스 누출, 아크, 화재 감지) | 즉시 EHS, 이 SOP보다 현장 비상 절차 우선 |
