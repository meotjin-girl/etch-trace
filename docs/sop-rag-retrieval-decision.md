# SOP 검색 문제 정의와 개선 방법 선택

작성일: 2026-10-20

대상: `mcp/sop_experiment.py`의 독립 검색 실험. Agent·기존 MCP 계약은 범위 밖이다.

**최종 선택: small 임베딩으로 후보 20개를 회수하고, LLM으로 조항 3개를 재순위화한다.**
모델 교체 단독 실험은 회귀가 있어 채택하지 않았다.

## 1. 해결할 문제

SOP/WI/SPEC 7개를 64개 조항으로 나누어 적재했지만, 사용자가 원문과 다른
표현으로 질문하거나 두 계통을 함께 물으면 필요한 조항이 top-3에서 누락된다.
목표는 문서 전체를 반환하는 것이 아니라 **답에 필요한 모든 조항을 top-3에 포함**하는 것이다.
답변 생성 전의 검색 문제이며, 이번 실험에서 원인 판정이나 장비 조치를 자동화하지 않는다.

기준선은 `text-embedding-3-small`, 1536차원, 정확 코사인 검색이다.
문서·청크·질문·정답·top-k를 고정하고 개선 방법 하나의 효과를 비교한다.

## 2. 관찰과 가설 구분

### 측정한 사실

- 원래 평가셋: 직접 질문 5개, 바꿔 말한 질문 5개, 복수 조항 질문 3개,
  문서 밖 질문 2개. 문서 밖 질문은 성공률에서 제외한다.
- 기준선: 직접 5/5, 바꿔 말한 질문 1/5, 복수 조항 2/3 → **8/13**.
- 실패한 조항은 전부 DB에 있고, 전체 검색 결과의 5~12위에 있다.
- 공통 주의문을 임베딩 입력에서 제외한 이전 실험도 8/13이었다.
- 근사 검색 인덱스는 사용하지 않으므로 ANN 후보 누락을 원인으로 볼 근거는 없다.

| 질문 | 필요한 조항 | 기준선 순위 | 관찰 |
|---|---|---:|---|
| P1: 반사 전력, 장비를 열기 전 점검 | `SPEC-RF-03#3` | 12 | RF 점검 대신 안전·에너지 차단 절차가 앞섬 |
| P3: 가스 유량을 영으로 설정, 영점 점검 | `WI-MFC-02#5.1` | 5 | 유량 검증·목적 절이 영점 절보다 앞섬 |
| P4: 세척 후 더미 웨이퍼 안정화 종료 | `WI-PM-07#3.6` | 8 | 목적·분해·세정 기록 절이 종료 조건보다 앞섬 |
| P5: 후면 냉각과 진공 압력 동반 변화 | `SOP-FC-01#4.3` | 8 | 일반 챔버 누설·조립 절이 FlowCool 판단 분기보다 앞섬 |
| M1: endpoint 지연과 RF 반복 상승 | `SOP-ETCH-12#4.2` / `SPEC-RF-03#2.4` | 7 / 1 | RF 관련 조항이 top-3를 차지하고 다른 주제의 근거가 누락됨 |

이는 단순 적재 실패가 아니라 **의미 대응과 순위의 문제**다.
관련성이 전혀 없는 결과만 나온다는 뜻은 아니다. 주제상 관련 있는 개요나 점검 절이
실제로 질문에 필요한 구체적인 판정·종료 조건 조항보다 앞서는 경우도 있다.

### 아직 가설인 것

- `reflected power / 반사 전력`, `zero / 영점`, `seasoning / 안정화`처럼
  한·영 표현이 다른 경우 현재 임베딩의 의미 대응이 약할 수 있다.
- 긴 절차와 여러 주제를 벡터 하나로 표현하면서 세부 조건이 덜 반영될 수 있다.
- 복수 주제 질문에서는 한 주제의 유사 조항들이 다른 주제의 근거를 밀어낼 수 있다.

현재 표본만으로 한국어 전체에 대한 모델 성능이나 긴 청크의 인과 효과를 단정하지 않는다.

### 별도 문제: 문서 밖 질문

거리 기준만으로 답변 가능 여부를 판정하지 않는다.
예를 들어 기준선에서 문서 밖 O1의 최근접 거리는 약 0.551이고,
답이 있는 P2의 정답 거리는 약 0.611이다.
O1을 거절하는 단순 거리 상한은 P2도 거절할 수 있다.
이번 개선은 검색 순위를 다루며, 답변 보류 정책은 해결했다고 주장하지 않는다.

## 3. 대안과 trade-off

| 방법 | 기대 효과 | 비용·복잡도 | 이번 판단 |
|---|---|---|---|
| top-k를 3에서 5로 늘림 | 가까운 누락 조항 일부 회수 | 반환량과 후속 LLM 입력 증가 | P3만 회복 가능하고 P1·P4·P5·M1은 남음. 원래 top-3 목표도 바뀌므로 채택하지 않음 |
| 한·영 용어 사전으로 질의 확장 | 알려진 용어 불일치에 직접 대응 | API 비용 증가 없이 구현 가능하나 사전 유지·동음이의어·평가셋 과적합 위험 | 실제 사용자 용어 목록이 없는 현재는 첫 선택에서 제외 |
| 키워드+벡터 하이브리드 검색 | 장비명·센서명·알람 코드의 정확 일치 보완 | 토큰화, 한국어 분석, 점수 결합 방식 추가 | 다른 말로 표현된 질문의 정확 키워드 부재를 단독 해결하지는 못함 |
| 작은 청크 또는 부모·자식 검색 | 긴 절의 세부 조건 회수 개선 가능 | 청크 ID·인용 단위·중복 결과 관리 필요 | 원문 조항 ID를 유지하는 현재 구조보다 변경 범위가 큼 |
| 질의 분해+문서 다양성 또는 재순위화 | M1처럼 복수 주제 누락 보완 가능 | 추가 모델 호출·지연·프롬프트 및 결과 검증 | 우선 단일 주제 순위 문제를 분리해서 개선 |
| **large 임베딩, 1536차원 유지** | 별도 용어 규칙 없이 의미 대응 개선 여부 확인 | 토큰 단가 상승, 문서 재임베딩 필요 | **먼저 비교할 방법으로 선택** |

## 4. 선택 이유와 비용

`text-embedding-3-large`를 `dimensions=1536`으로 요청한다.
청크·질문·거리 함수·최종 top-3는 변경하지 않는다.
질의 확장·추가 생성 모델·재순위화를 동시에 적용하지 않아 개선 요인을 분리한다.
공식 모델 벤치마크만으로 이 프로젝트의 효과를 보장하지 않고 실제 결과로 채택 여부를 판단한다.

2026-10-20 확인한 공식 표준 임베딩 입력 단가는 100만 토큰당
small $0.02, large $0.13으로 **6.5배**다.
차원 수를 1536으로 맞춰 모델 하나당 벡터 저장 크기는 유지한다.
비교 실험에서는 두 모델의 벡터를 모두 보존하므로 전체 보관량은 늘어난다.

| 입력 | small 추정 API 비용 | large 추정 API 비용 |
|---|---:|---:|
| 원문 10,807토큰 1회 적재 | $0.00021614 | $0.00140491 |
| 원래 평가 질문 577토큰 1회 | $0.00001154 | $0.00007501 |

위 값은 공개 토큰 단가를 적용한 추정이며 실제 청구 확인값이 아니다.
이번 데이터 크기에서는 절대 비용이 작지만, 운영 질의량이 늘면 같은 배율의 비용 차이가 남는다.
모델 변경 시 문서 벡터도 다시 만들어야 한다. 기존 벡터와 다른 모델의 질문 벡터를 섞지 않는다.

## 5. 구현과 평가 규칙

- `Embedder`가 모델과 API 클라이언트를 소유하고, 결과 `Embedding`에도 모델을 붙인다.
- `sop_rag_model_chunks`의 키를 `(model, id)`로 두고 조회·캐시·삭제 모두 모델별로 제한한다.
- 기존 `sop_rag_chunks`는 초기 실험 스냅샷으로 남기며 삭제하거나 덮어쓰지 않는다.
- 각 명령의 `--model`로 small과 large를 재현할 수 있게 한다.
- 평가는 top-3 성공 여부와 별도로 정답 조항의 전체 순위를 기록한다.
- 질문 파일 SHA-256, 질문 임베딩 토큰 수와 배치 소요 시간도 결과 JSON에 남긴다.
- 원래 15문항의 질문과 정답은 변경하지 않는다. 목표는 그대로 **11/13 이상**이다.
- 비교 실행 전에 추가 10문항을 `mcp/sop_questions_holdout.json`에 고정한다.
  답이 있는 8문항과 근접·비관련 문서 밖 질문 2문항이며, 보조 목표는 7/8이다.
- 추가 문항도 같은 작성자가 만든 작은 점검 세트다. 독립적으로 수집한 운영 평가셋이 아니며,
  일반화 성능이나 통계적 유의성을 입증하는 자료로 해석하지 않는다.
- 기존 성공 문항이 회귀하는지와 추가 세트에서 악화가 생기는지도 비교한다.
- 소요 시간은 한 번의 배치 관찰값으로 기록하고 모델별 평균 지연이나 성능 보장으로 해석하지 않는다.

## 6. 첫 가설 검증: large 단독 교체는 채택하지 않음

| 방법 | 직접 질문 | 바꿔 말한 질문 | 복수 조항 | 원래 세트 합계 | 추가 세트 |
|---|---:|---:|---:|---:|---:|
| small + dense top-3 | 5/5 | 1/5 | 2/3 | 8/13 | 5/8 |
| large + dense top-3 | 5/5 | 4/5 | 0/3 | 9/13 | 6/8 |

large는 P1·P3·P5를 회복했지만 M2·M3를 잃었다.
추가 세트에서도 H1·H2를 회복한 대신 H6가 실패했다.
따라서 단가 상승을 감수하고 large로 바꾸는 것만으로 목표를 충족하지 못했다.
모델이 커지면 모든 질문이 좋아진다는 가정은 이 실험에서 성립하지 않았다.

## 7. 방법 재선택: 넓게 회수한 뒤 필요한 근거를 고름

small 모델에서도 원래 실패한 모든 정답 조항이 12위 안에 있었다.
이는 후보를 회수할 능력이 전혀 없는 문제가 아니라 **회수한 후보에서 필요한
조항을 좁히는 단계가 부족한 문제**라는 해석을 뒷받침한다.

선택한 두 단계는 다음과 같다.

1. small 임베딩의 정확 코사인 검색으로 **후보 20개**를 회수한다.
2. `gpt-4.1-mini`에 질문과 후보 원문을 주고, 후보 안의 조항 ID **3개만** 선택하게 한다.

후보 수 20은 이 작은 문서 집합에서 회수 여유와 요청 크기를 절충한 실험 설정이다.
최종 top-k는 여전히 3이며, 20개를 답으로 반환해서 성공률을 높인 것이 아니다.
후보 수를 여러 값으로 탐색해 평가 점수가 좋은 값만 고르는 과정은 수행하지 않았다.

재순위화 기준은 특정 정답 ID가 아니라 구체적 절차·판정 기준·종료 조건을
일반 개요보다 우선하고, 복수 주제 질문에서는 각 주제를 덮는 근거를 고르는 것이다.
평가 질문·정답·질문별 분기나 수작업 용어 사전은 코드에 넣지 않았다.

### 감수하는 trade-off

- 질의당 생성 API 호출 1회와 후보 원문 전송이 추가된다.
- 임베딩만 사용하는 검색보다 비용·지연·외부 모델 의존성이 커진다.
- 대신 원문 재분할이나 문서 재임베딩 없이 순위와 복수 근거 선택을 개선할 수 있다.
- 구조화 응답은 ID 3개로 제한하고, 중복·후보 밖 ID는 오류로 거절한다.
  실패를 빈 결과나 dense 순위로 조용히 대체하지 않는다.
- 반환되는 원문·개정·시연 표시·출처는 기존 후보 객체 그대로다.
- 결과의 `distance`는 **원래 코사인 거리**다. 재순위화 점수가 아니므로
  재순위화 결과의 거리 값은 오름차순일 필요가 없다.

small 기준선에서 성공했던 문항의 회귀는 없었다.
질문과 정답 파일은 모델 비교 및 재순위화 실험 내내 동일하게 유지했다.

### 추가 비용과 지연 관찰값

| 세트 | 재순위화 호출 | 입력 토큰 | 출력 토큰 | 재순위화 총 시간 | 추정 API 비용 |
|---|---:|---:|---:|---:|---:|
| 원래 15문항 | 15 | 49,388 | 553 | 18.47초 | $0.0206400 |
| 추가 10문항 | 10 | 34,507 | 369 | 13.59초 | $0.0143932 |

가격은 공식 모델 페이지의 100만 토큰당 입력 $0.40·출력 $1.60을 적용했다.
두 평가 합계는 약 $0.0350으로, 실제 청구 확인값이 아닌 비캐시 표준 단가 추정이다.
별도 진단·대화형 검색·임베딩 적재 비용은 이 표에 포함하지 않는다.
원래·추가 세트에서 관찰한 질의당 재순위화 시간은 각각 약 1.23초·1.36초다.
한 번의 실행 관찰값이며 네트워크·부하·캐시가 다른 환경의 평균이나 상한을 뜻하지 않는다.

### 코드와 검증

- `mcp/sop_vectors.py`: 모델별 임베딩·캐시·검색·삭제 격리
- `mcp/sop_rerank.py`: 후보 ID만 선택하는 구조화 재순위화
- `mcp/sop_experiment.py`: 기본 방법을 `rerank`로 설정하고 비교 옵션·진단 정보 제공
- `tests/test_sop_retrieval.py`: 실제 pgvector와 모델 격리·캐시·CLI 경계
- `tests/test_sop_rerank.py`: ID 재정렬 시 근거 보존, 중복·허위 ID 거절, 응답 개수

관련 테스트 **20개 통과**, MCP 환경을 지정한 타입 검사 **오류 0·경고 0**,
린트·형식 검사 통과를 확인했다.

## 9. 재현

저장소 루트에서 실행한다. DB와 키 파일 준비는 `mcp/SOP_EXPERIMENT.md`를 따른다.

```sh
# 두 모델의 원문 벡터를 별도로 준비한다. 변경 없는 모델은 재사용한다.
uv run --project mcp --group rag-experiment python mcp/sop_experiment.py ingest \
  --model text-embedding-3-small
uv run --project mcp --group rag-experiment python mcp/sop_experiment.py ingest \
  --model text-embedding-3-large

# 기준선은 원래 목표 미달이므로 종료 코드 1이 정상적인 관찰 결과다.
uv run --project mcp --group rag-experiment python mcp/sop_experiment.py evaluate \
  --model text-embedding-3-small --method dense --output outputs/sop-small-original.json
uv run --project mcp --group rag-experiment python mcp/sop_experiment.py evaluate \
  --model text-embedding-3-large --method dense --output outputs/sop-large-original.json

# 최종 방법: 원래 top-3 목표와 질문을 그대로 사용한다.
uv run --project mcp --group rag-experiment python mcp/sop_experiment.py evaluate \
  --model text-embedding-3-small --method rerank --output outputs/sop-rerank-original.json
uv run --project mcp --group rag-experiment python mcp/sop_experiment.py evaluate \
  --model text-embedding-3-small --method rerank \
  --questions-file mcp/sop_questions_holdout.json --minimum-passed 7 \
  --output outputs/sop-rerank-holdout.json
```

추가 세트의 dense 비교는 위 명령에서 `--method dense`를 사용하고,
`--model`을 각각 small과 large로 바꾸어 재현한다.
`--minimum-passed 7`은 8개 답변 가능 문항에 대한 보조 목표이며
원래 13문항의 목표 11을 낮춘 것이 아니다.

전체 원문을 담은 JSON은 `outputs/`의 로컬 산출물이다.
비교 결과의 핵심 수치와 판단은 Git에 남길 수 있도록 이 Markdown에도 기록했다.

## 10. 남은 한계

- 원래·추가 세트는 같은 문서에서 만든 작은 개발 평가셋이다.
  추가 세트 결과도 방법 재선택 전에 확인했으므로 최종 방법의 독립 블라인드 테스트가 아니다.
  **13/13과 8/8은 이 고정 문항에서의 관찰값이지 운영 정확도 100%가 아니다.**
- 문서 밖 질문도 후보 중 3개를 반환한다. 답변 가능성 판정과 답변 보류는 구현하지 않았다.
- 후보 20개 안에 근거가 없으면 재순위화로 복구할 수 없다. 문서가 늘면 후보 회수율도 다시 측정해야 한다.
- 생성 모델은 `temperature=0`이어도 결과가 항상 동일하다고 보장할 수 없다.
  단위 테스트는 외부 모델 응답 대신 결정적인 ID 검증을 검사하며, 실제 평가는 별도로 측정했다.
- `gpt-4.1-mini`는 이번 키로 실제 호출을 확인한 실험 모델이다.
  확인한 공식 모델 페이지에는 Deprecated로 표시되어 있어 운영 모델로 장기 지원을 가정하지 않는다.
- SOP의 예시 수치와 역할 설명은 별도로 검토할 문서 내용이며 검색 개선으로 검증된 것이 아니다.
