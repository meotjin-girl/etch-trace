4.1 동기 경로 vs 비동기 경로

경로거치는 일응답
동기 (수백 ms)run 검색, 작업 목록·상태 조회, 승인·거절 기록, 관리자 지표200 즉시
비동기 (수 초~수십 초)Agent 조사, 보고서 재작성, 문서 재색인, 승인 후 재개202 후 SSE 이벤트

S4. (📐 설계) Kafka 대기열 · 재시도 · DLQ — 평가 가산점 항목

sequenceDiagram
  autonumber
  participant B as Spring Boot
  participant K as Kafka
  participant A1 as Agent worker #1
  participant A2 as Agent worker #2
  participant DB as PostgreSQL

  B->>DB: INSERT tasks (QUEUED)
  B->>K: trace.tasks.requested key=taskId

  else 최대 재시도(3) 초과
    A1->>K: trace.tasks.dlq {taskId, error, trace_id}
    A1->>K: trace.tasks.events FAILED
  end
  A1->>K: trace.tasks.events (PLAN/TOOL_*/APPROVAL_REQUIRED/DONE)
  K->>B: consume events
  B->>DB: INSERT task_events, UPDATE tasks
  B-->>B: SseEmitter로 해당 taskId 구독자에게 push

토픽key생산자 → 소비자비고
trace.tasks.requestedtaskIdSpring → Agent파티션 key로 같은 작업 순서 보장
trace.tasks.resumetaskIdSpring → Agent승인/수정 요청 Command(resume)
trace.tasks.retrytaskIdAgent → Agentattempt, backoff(2s·8s·30s)
trace.tasks.dlqtaskIdAgent → 관리자 화면실패 원인 + trace id
trace.tasks.eventstaskIdAgent → Spring현 task_events 행과 1:1 (스키마 동일)

멱등성: checkpointer가 thread_id 단위로 진행을 저장하고, investigations.task_id UNIQUE + 조건부 상태 UPDATE로 재처리해도 중복 저장되지 않는다.
